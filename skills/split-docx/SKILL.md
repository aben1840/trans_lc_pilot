# 按标题拆分 docx

拆分操作基于**某一标题级别**进行，选择哪个级别需要自行判断：同一份文档按一级标题和按二级标题拆分，会得到不同的片段，这里没有唯一"正确"答案。因此 CLI 会先报告文档有哪些级别，再由用户做出选择。**绝不要**静默地替用户选一个级别。

## 步骤

1. **获取文件路径。** 如果用户没有指定文件，先询问。相对路径以当前工作目录（CWD）为基准解析。

2. **转换 docx 并打开预览。** 这一步把文档呈现在用户面前：

   ```bash
   uv run trans-lc-pilot --convert <file>
   ```

   该命令会将源 docx 转换为 HTML 并在浏览器中打开。告知用户文档已打开。
   只有在无法弹出浏览器（无头环境或远程会话）时才加 `--quiet`。

   这是用户在第 4 步选择标题级别时参考的内容。拆分生成的 `index.html` 会在之后单独打开——见第 5 步。

3. **检查标题结构——绝不要盲目拆分。**

   ```bash
   uv run trans-lc-pilot --list-levels <file>
   ```

   该命令不会写文件，只会输出每个存在的标题级别及其数量，例如 `h2: 5`。
   如果显示 `no headings found`，说明文档完全没有使用标题样式。

4. **展示清单和候选项，然后让用户选择。**
   转换后的文档已经显示在屏幕上，所以可以对照说明每个级别会产生什么结果——例如："文档有 5 个 H2，没有 H1，因此按 H2 拆分得到 5 篇，而 H1 根本没有边界。"
   只有当用户已经明确指定了某个级别时，才跳过这一问。

   这里的标题指的是 Word 的**标题样式**（由 mammoth 映射）。加粗或大号文字不算标题，所以一份文档完全合法地可能没有任何标题——这是文档本身的事实，不是错误。

5. **执行拆分——索引页会自动打开。**

   ```bash
   uv run trans-lc-pilot --split <file> --level N
   ```

   这一步会写出各个片段并打开 `index.html`，用户可以点击查看拆分结果。告知用户索引页已打开。如果无法弹出浏览器（无头环境或远程会话），加 `--quiet` 可抑制打开动作。

6. **如实汇报实际发生了什么**，以命令的输出为准。有两种结果容易被误读，需要特别指出：

   - **`articles: 1`** 同时伴随一行 `note:` —— 说明该标题级别下没有任何标题，文档被完整保留。要直白地说明这一点，并重新列出文档实际具有的标题级别，方便用户换一个级别重试。
   - **前置内容**（`000-preamble.html`）—— 出现在第一个标题之前的内容。它是前置材料，不是一篇文章；要明确称之为前置内容。

7. **询问拆分结果是否符合预期。** 索引页就在屏幕上，此时是确认的好时机：告诉用户一共有多少个片段，问这是否符合他们的需求。如果不符合，就用第 4 步列出的其他级别作为替代——重新执行第 5 步，换一个级别。不要只汇报就结束，一定要等用户确认。

## 注意事项

- 输出文件存放在 `CWD/.tmp/` 下：`--convert` 生成一个 `docproj-source-XXXX.html`，`--split` 生成一个 `articles-XXXX/` 目录，里面包含每个片段对应的文件以及一个链接所有片段的 `index.html`。名称是随机的，也不会自动清理。两者都会在各自的步骤中自动在浏览器打开——文档在第 2 步，索引页在第 5 步——加 `--quiet` 可以抑制打开。
- 拆分产出的是 HTML，不是 docx。
- `--level` 只接受 1–6 之间的数字；其他值会在 argparse 校验阶段就被拒绝，不会触碰文档。
- 失败时会打印 `error: ...` 并以非零状态码退出。直接把错误信息转告用户，不要自己猜测路径后盲目重试。
